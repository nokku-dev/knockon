# 仕様書の同期ルール

ユーザーフィードバックや実装判断で SPEC.md（および DESIGN-SYSTEM.md がある場合はそれも）と異なる選択をした場合、必ず以下のどちらかを同時に実施する:

1. **SPEC.md / DESIGN-SYSTEM.md を更新して実装に合わせる**
2. **「対応しない」判断の理由を該当ファイルにコメントとして残す**

## なぜこのルールが必要か

実装後に差分チェックすると、意図的な変更が「未実装」として誤検知される。再度同じ議論が必要になり、時間を浪費する。仕様書と実装の乖離は放置するほど埋めるコストが増える。

## 具体例

- ユーザーが「キューカードはフラットにして」と言った
  - → SPEC.md / DESIGN-SYSTEM.md の該当セクションを同じ PR で更新する
- ユーザーが「リストはカードじゃなくて行で並べて」と言った
  - → SPEC.md / DESIGN-SYSTEM.md の該当箇所を更新する

## タイミング

- **コミット前**: 実装変更と仕様書変更は同じコミット／PR に含める
- **PR レビュー時**: 仕様書の更新がない場合、レビュアーは指摘する
