## 手順

### 1. 変更内容の確認

- `git status` で変更ファイルを確認
- `git diff` で差分の概要を把握
- 変更がない場合は「コミットする変更がありません」と報告して終了

### 2. テスト実行

- プロジェクトのテストコマンドを実行（CLAUDE.md のビルド・テストコマンドを参照）
- テストが失敗した場合は停止し、ユーザーに報告する。PRは作らない

### 3. コミット

- 変更内容から Conventional Commits 形式のコミットメッセージを生成
- 関連する Issue 番号があればメッセージに含める（例: `fix: OCR精度閾値の修正 #12`）
- コミットメッセージをユーザーに提示し、確認を得てから `git add` → `git commit`
- 複数の目的が混在している場合はコミットを分割する

### 4. Push

- `git push origin HEAD`
- リモートブランチが存在しない場合は `git push -u origin HEAD`

### 5. PR作成

`.github/pull_request_template.md` に沿ってPRを作成する:

- **概要**: 変更内容から自動生成
- **テストチェックリスト**: 実装したテストケースから抽出
- **予測**: 変更の影響について予測を記載
- **変更内容**: 主要な変更点を箇条書き
- **TodoistタスクID**: /start で作成した Issue に記載があれば引き継ぐ
- **Closes #XX**: 対応する Issue 番号を自動付与

`gh pr create` で作成。ドラフトではなくレビュー可能な状態で作る。

### 6. 自動レビュー

PR作成後、code-reviewer エージェントを呼び出してレビューを実行する。

- Critical の指摘がある場合: ユーザーに報告し、修正するか聞く
- Major/Minor のみの場合: レビュー結果を表示し、対応はユーザー判断に委ねる

### 7. TODO.md 更新

- TODO.md の「進行中」から該当タスクを「完了」に移動
- Issue番号、ブランチ名、PR番号を記録

### 8. 完了報告

```
🚀 Ship 完了

コミット: <コミットメッセージ>
PR: <PR URL>
レビュー結果: Critical 0 / Major X / Minor Y

次のアクション:
- レビュー指摘があれば対応してください
- マージ後に /learn で知見を記録できます
```

### 注意

- テストが通らない状態ではPRを作らない
- コミットメッセージは必ずユーザーに確認する
- force push は絶対にしない
