## 前提

setup.sh が既に実行済みで、CLAUDE.md 等のテンプレートファイルが存在していること。

## 手順

### 1. 現状確認

CLAUDE.md を読み、`{{...}}` プレースホルダーが残っているか確認する。
既に埋まっている場合は「初期設定は完了済みです」と報告して終了。

### 2. リポジトリの既存情報をスキャン

以下のファイル・情報を読み取り、プレースホルダーに対応する情報を自動抽出する:

**読み取り対象:**
- `README.md` → プロジェクト名、概要
- `package.json` / `Cargo.toml` / `pyproject.toml` / `build.gradle` 等 → 技術スタック、ビルド・テストコマンド、依存関係
- `.gitignore` → 使用技術の手がかり（node_modules → Node.js、*.meta → Unity 等）
- ディレクトリ構成 → 主要ディレクトリと役割
- 既存のCI設定（`.github/workflows/`）→ ビルド・テストコマンド
- `git log --oneline -20` → プロジェクトの活動状況、現在のフェーズの手がかり

**抽出結果をマッピング:**
| プレースホルダー | 自動抽出元 |
|---|---|
| `{{PROJECT_NAME}}` | package.json の name / README.md のタイトル / ディレクトリ名 |
| `{{1-2文でプロジェクトの目的を書く}}` | README.md の冒頭 |
| `{{主要な技術・フレームワーク・SDK}}` | package.json の dependencies / ファイル拡張子 / 設定ファイル |
| `{{パッケージマネージャ}}` | lock ファイルの種類（yarn.lock → yarn, pnpm-lock.yaml → pnpm 等） |
| ビルド・テストコマンド | package.json の scripts / CI設定 |
| ディレクトリ構成 | 実際のディレクトリ構造 |

### 3. 抽出結果をユーザーに提示して確認

自動抽出した内容を一覧で表示する:

```
📋 リポジトリから読み取った情報:

プロジェクト名: Cardex
概要: 手書きノートをカメラで撮影し、AIでOCR・タグ付けして検索可能にするアプリ
技術スタック: React Native / Expo / Claude API
パッケージマネージャ: npm
テストコマンド: npm test
...

この内容で CLAUDE.md を埋めてよいですか？修正があれば教えてください。
```

**自動抽出できなかった項目のみ質問する。** 全部聞き直さない。

### 4. 追加情報を対話で収集

自動抽出では得られない情報を聞く:

**常に聞く:**
- Augmentation原則のこのプロジェクトでの具体化（「ユーザーに何を要求しないか」）
- プロジェクト固有の注意点・制約（あれば）

**PLAN.md が存在する場合のみ:**
- 現在のフェーズ（MVP / α / β / 本番運用）
- 直近の方向性

**任意（わからなければスキップ）:**
- レビューロールのカスタマイズ

### 5. ファイルを更新

収集した情報で以下のファイルのプレースホルダーを置換する:

- **CLAUDE.md**: 全プレースホルダー
- **PLAN.md**: ビジョン、現在のフェーズ、直近の方向性（存在する場合）
- **.claude/settings.json**: 技術スタックに応じた許可コマンドを追加
  - 例: Node.js系なら `Bash(npm *)`, `Bash(npx *)` を allow に追加
  - 例: Unity系なら該当するCLIコマンドを追加
  - 例: Python系なら `Bash(pip *)`, `Bash(python *)` を allow に追加

### 6. 確認

更新したファイルの最終内容をユーザーに見せ、問題なければ完了。
修正があればその場で対応する。

### 7. 次のステップを案内

```
✅ 初期セットアップ完了

次のステップ:
- /start でTodoistタスクからIssueを作成して作業開始できます
- understanding-map.md は /map で更新できます
- 作業中にハマったら /learn で知見を記録できます
```
