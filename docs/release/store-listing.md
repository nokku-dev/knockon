## 0. ASO の前提（どの枠が検索に効くか）

App Store が**検索インデックスに使うのは 3 つだけ**。ここを外すと検索流入が発生しない。

| 枠 | 検索の重み | 備考 |
| --- | --- | --- |
| アプリ名 (30字) | **最大** | `knockon` は造語のため検索語としては機能しない |
| **サブタイトル (30字)** | **次点** | **カテゴリ語を置く唯一の実質的な場所** |
| キーワード欄 (100字) | 中 | 非公開。名前 / サブタイトルとの重複は枠の無駄 |
| 説明文 (4000字) | **対象外** | Google Play と違い**インデックスされない**。CVR にのみ効く |
| スクショのキャプション | signal | 2025 年半ばから OCR で抽出される。**先頭 3 枚**の重みが最大 |

> ⚠️ **初稿はこれを踏まえていなかった**。説明文に注力する一方でサブタイトルに検索語がゼロで、
> 重みの大きい枠を空にしていた（2026-07-31 にユーザー指摘で改訂）。

**アプリ名は `knockon` のまま**とする。名前の重みは最大だが、ダウンロード 0 の新規アプリが
`習慣` のような競合語で上位に入るのは現実的でなく（ランキングは download velocity と retention が支配的）、
一方で ADR-0005（プロダクト名 = `knockon`）と CLAUDE.md §6 に触れる確実なコストがある。
**名前もサブタイトルも将来のバージョンで変更できる**ので、実データを見てから判断する。

## 1. アプリ名 (30 文字以内)

```
knockon
```

- 7 文字 (上限 30)。
- 日本語名を併記しない: プロダクト名は 1 箇所に集約する方針 (CLAUDE.md §6「プロダクト名を user-facing 文字列にハードコードせず 1 箇所に集約」の精神)。読みは「ノックオン」だが表記は英字で固定する。

## 2. サブタイトル (30 文字以内)

```
連鎖でつづく習慣・ルーティン記録
```

- 16 文字 (上限 30)。
- **ASO 上ここは検索インデックス対象**（重みはアプリ名に次ぐ 2 番目）。説明文は**インデックス対象外**なので、
  検索語を置けるのは アプリ名 / サブタイトル / キーワード欄 の 3 つだけ。
  そのためサブタイトルに **カテゴリ語を 3 つ**（`習慣` / `ルーティン` / `記録`）詰めている。
- **初見で何のアプリか分かること**を最優先した。`knockon` は造語なので、サブタイトルが
  カテゴリを伝える唯一の場所になる。
- ❌ **不採用にした案と理由**:
  - 「続いた線が、そのまま実績になる」(初稿) — **検索語がゼロ**で、かつ初見では習慣アプリだと分からない。
    ブランドの語り口を優先して ASO と伝達の両方を落としていた
  - 「途切れても減らない習慣アプリ」 — 差別化(反 streak)は言えているが、**文脈を知らない人には
    「何が減らないのか」が伝わらない**（ユーザー判断 2026-07-31）
  - 「習慣を続ける新しい方法」— 一般的すぎて差別化がない
  - 「ストリークに疲れた人の習慣アプリ」— 競合を否定する形になり ANT と反する

## 3. カテゴリ

- **プライマリ: 仕事効率化 (Productivity)**
- **セカンダリ: ヘルスケア/フィットネス (Health & Fitness)**

**判断**: プライマリは仕事効率化。knockon は行動の実行管理（If-Then で次の行動に繋ぐ）が本体で、
健康指標は任意の付随機能 ([ADR-0024](../decisions/0024-goal-view-analytics-phase-3-unified.md) 「メトリクスは任意 + チェーンと疎結合」)。
ヘルスケアをプライマリにすると、健康アプリとして評価され「機能が薄い」と見られるリスクがある。

> ⚠️ ライフスタイルは採らない。playbook §1.2 は「ライフスタイル or ヘルスケア/フィットネス」と書いていたが、
> ライフスタイルは競合が雑多で埋もれやすく、習慣アプリの主戦場は仕事効率化。

## 5. 説明文 (4000 文字以内)

```
knockon は、ひとつの行動が次の行動を呼ぶ「連なり」で習慣を組み立てるアプリです。

■ 「時間」ではなく「直前の行動」を引き金にする

多くの習慣アプリは「毎朝7時に運動する」のように時刻でリマインドします。
けれど実際に私たちが続けられている習慣は、たいてい別の行動にくっついています。
歯を磨いたらストレッチをする。コーヒーを淹れたら机に向かう。

knockon はこの構造をそのまま形にします。
起点をひとつ決めて、そこから行動を数珠つなぎにしていく。
2つめ以降の行動に時刻を設定する必要はありません。直前の行動が終わったことが、次の合図になります。

この考え方は If-Then プランニング（実行意図）と呼ばれ、
94件の研究を集めた分析で、行動の実行率を高めることが確かめられています。

■ 連続日数を数えません

knockon には連続日数のカウンターがありません。炎のアイコンも、途切れたことを知らせる赤い表示もありません。

理由は単純で、連続日数は「失われうる数字」だからです。
数えはじめると、途切れた日にアプリを開きたくなくなります。
本来は続けるための道具が、続けられなかったことを突きつける道具に変わってしまう。

そこで knockon が見せるのは、増えることはあっても減らないものだけにしました。

・積み上がっていく線
・繰り返すうちに定着した行動につく星
・これまでに定着した数

3日空いても、1週間空いても、あなたがこれまでに積み上げたものは何ひとつ減りません。
またタップすれば、そこから続きが伸びていきます。

■ 開いて、タップするだけ

その日に実行する行動は、アプリを開けばすべて並んでいます。
やったものをタップする。それだけです。

通知や位置情報の設定は任意です。
設定しなくても使えるように作ってあります。
「正しく設定できた人だけがうまく使える」道具にはしたくなかったからです。

■ 主な機能

・行動の連なり（チェーン）をいくつでも作成
・起点は時刻でも、場所でも、行動でも
・1日の区切り時刻を変更可能（深夜に活動する人向け）
・2週間のうち10日実行すると「定着」になる（一度ついた定着は消えません）
・育成中・もう少しで定着・定着 の3段階で一覧
・体重などの数値を任意で記録し、推移を確認
・使わない期間のチェーンは削除せず休止できる

■ データについて

記録した内容は、すべて端末の中だけに保存されます。
チェーンの名前も、メモも、体重などの数値も、外部に送信されることはありません。
すべての機能を無料で使えます。アカウント登録は不要で、広告もありません。

アプリの改善のため、個人を特定しない匿名の利用統計と不具合情報のみを収集しています。

※ 記録は端末内にのみ保存されます。機種変更や端末の初期化、アプリの削除を行った場合、
記録は引き継がれません。

■ こんな方に

・習慣アプリを試したものの、連続記録が途切れて使わなくなった
・やることは分かっているのに、順番に着手できない
・朝や夜のルーティンを、ひとつの流れとして固めたい

---

プライバシーポリシー: https://legal.nokku.dev/knockon/privacy
利用規約: https://legal.nokku.dev/knockon/terms
```

- 1,391 文字（上限 4000 に対して余裕あり）。
- **構成の意図**: 冒頭 3 行で差別化 (If-Then) → 反 streak の理由 → 使い方の軽さ → 機能列挙 → プライバシー → 対象読者。
  App Store の説明文は**最初の 2〜3 行しか展開せずに読まれない**ため、差別化を先頭に置いた。
- **論文の引用形式は説明文から外した** (2026-07-31 レビュー)。一般ユーザーに
  `Gollwitzer & Sheeran, 2006` はノイズで、**それは審査員が読む §9 App Review メモの仕事**。
  読者を取り違えていた。事実 (94 件の分析) は残し、出典表記だけ落としている。
- **「定着」の条件を明記した**。星・定着数・3 段階と何度も出てくるのに条件が書かれておらず、
  読者が「3 日で貰えるのか 3 ヶ月かかるのか」を判断できなかった。**アプリの中心的な報酬が
  届くものか分からない**状態だったため、「2 週間のうち 10 日」を書いて目標として機能させる。
- **無料であることを明記した** (ADR-0048)。コンバージョンに効くのに書かれていなかった。
- **データ消失の注記を「失われます」→「引き継がれません」に差し替えた** (2026-07-31)。
  同期もエクスポート導線も無い以上、**代替手段を提示できないことは変えていない**。
  事実の精度を落とさずに、インストール直前の読者へ不必要な不安を与える語感だけ外した。
  ⚠️ 誇張・省略ではないので、**同期やバックアップを実装したらこの記述を必ず更新する**。
- ⚠️ **書いていないこと**: 研究タブ ([ADR-0049](../decisions/0049-exclude-research-tab-from-release-scope.md) でリリース非表示) と
  マトリクス ([ADR-0051](../decisions/0051-remove-matrix-and-merge-fresh-into-growing.md) で撤去) には触れていない。
  実装にない機能を書くと playbook §4.5 (Guideline 2.3.3) のリスクになる。
- ⚠️ **Notion 連携には触れていない**。[ADR-0052](../decisions/0052-remove-notion-metrics-integration.md) で
  機能ごと撤去済み。
- ⚠️ **説明文とプライバシーポリシー / Nutrition Label は必ず一致させる**
  ([ADR-0053](../decisions/0053-analytics-platform-posthog.md))。片方だけ直すと審査で刺さる。

## 6. キーワード (100 文字以内・カンマ区切り)

```
三日坊主,習慣化,習慣トラッカー,習慣管理,継続,朝活,ナイトルーティン,モーニング,積み上げ,定着,セルフケア,ルーチン,毎日,チェックリスト
```

- **最重要は `三日坊主`**。日本人が**この問題をまさにその言葉で検索する**語で、knockon の売りと一致する。
- ❌ **外した語と理由**:
  - `if-then` — 日本語ストアで日本人は検索しない。字数の無駄
  - `行動` — 汎用すぎて検索意図がない
  - `タスク` — 競合が激しいうえ **knockon はタスク管理アプリではない**。ミスマッチな流入は
    継続率を下げ、**継続率自体がランキングシグナル**なので逆効果になる
- **アプリ名・サブタイトルに入れた語はここに入れない**（Apple は名前とサブタイトルも検索対象にするため、
  重複は 100 字の枠を捨てることになる）。サブタイトルに `習慣` / `ルーティン` / `記録` を移したので、
  ここからは外した。
- スペースを入れず**カンマのみで区切る**（スペースは 1 文字消費する）。
- 「ストリーク」は入れない: 検索で来た人の期待と中身が正反対になり、低評価レビューの原因になる。

## 9. App Review 情報 (審査担当者向けメモ)

```
ローカル完結のオフライン習慣アプリです。アカウント登録・ログインはありません。
デモアカウントは不要です。

主要な操作フロー:
1. 初回起動 → オンボーディングで用意されたチェーン(行動の連なり)を選んで追加
2. 「Today」タブに当日の行動が並ぶ
3. 各行動をタップして実行済みにする

設計上の補足:
- ユーザーが記録した内容(チェーン名・メモ・身体指標の数値・場所の座標)は
  端末内の SQLite にのみ保存され、外部に送信されません。
- アプリの改善のため、製品分析サービス PostHog を用いて匿名の利用統計と
  不具合情報のみを収集しています(EU 内で処理)。個人の特定や、他社サービスを
  またいだ追跡は行いません。画面の録画も行いません。
- 位置情報は、ユーザーが「場所」を起点として登録した場合にのみ使用します。
  用途は2つで、(1)場所を登録するときの現在地取得、(2)登録した場所への到達検知です。
  到達検知には OS 標準のジオフェンス(リージョンモニタリング)のみを用い、
  継続的な位置の追跡や記録は行いません。位置座標が端末外に送信されることも
  ありません。外部の地図APIも呼び出しません。
  許可しなくてもアプリの中心機能は利用できます(到達時の通知が出ないだけで、
  一覧から手動で実行済みにできます)。
- 通知はローカル通知のみで、サーバープッシュは使用していません。
- 本アプリの設計は If-Then プランニング(実行意図)の研究に基づいています
  (Gollwitzer & Sheeran, 2006. 94件のメタ分析)。
```

- **位置情報と通知の説明を先回りして書く**: playbook §4.3 (Guideline 5.1.1) / §4.4 (Guideline 4.5.4) の
  リジェクト理由に対応する。指摘されてから答えるより往復が減る。
