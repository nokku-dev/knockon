# App Store 6.5" スクリーンショット (1284×2778)

> 生成元: [../6.7/](../6.7/) の 1290×2796 を `sips -z 2778 1284` でリサイズしたもの。
> **再撮影ではない**。実機で撮った画面そのままで、寸法だけ合わせている。

## なぜ必要になったか

App Store Connect のスクリーンショット枠は表示サイズごとに分かれており、
**6.5 インチの枠は 1242×2688 / 1284×2778 しか受け付けない**。6.7"/6.9" 用に撮った
1290×2796 をそこにドラッグすると「寸法が正しくありません」で弾かれる (2026-07-31)。

## まず 6.9" の枠を使うこと

**本来こちらは不要**。Apple は最大サイズを 1 セット入れれば他サイズへ自動スケールする。
ASC の「メディアマネージャですべてのサイズを表示」から **6.9 インチ (または 6.7 インチ)**
の枠を開き、[../6.7/](../6.7/) の 1290×2796 を**加工なしで**入れるのが正規ルート。

本ディレクトリは、6.9" の枠が見つからない / 使えない場合のフォールバック。

## リサイズの妥当性

- 1290×2796 → 1284×2778 は**縦横比の差が 0.17%**（0.4614 → 0.4622）。目視で判別できない
- Guideline 2.3.3 が問題にするのは**内容の正確さ**（アプリに無い機能を見せない / 実画面が
  マーケ素材で隠れない）であって、寸法合わせのリサイズは対象外
- 装飾・テキスト追加は**していない**（[../6.7/README.md](../6.7/README.md) の方針を維持）

## 再生成

6.7" を撮り直したら、以下で作り直す。

```sh
cd docs/release/screenshots
mkdir -p 6.5
for f in 6.7/*.png; do
  b=$(basename "$f")
  cp "$f" "6.5/$b"
  sips -z 2778 1284 "6.5/$b"
done
```
