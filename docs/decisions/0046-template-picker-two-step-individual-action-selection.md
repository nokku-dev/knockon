# テンプレから追加の UI を 1-step 一括追加から 2-step 個別選択に改定 (ADR-0023 PR-Y1 挙動条文改定)

## 文脈

[ADR-0023](0023-template-chains-and-subchain-implementation-plan.md) §想定される影響 (PR-Y1 範囲) では PR-Y1 の挙動を次のように書いていた:

> テンプレ選択モーダル → 選択 → 各アクションを INSERT (新規 action として) + ノード末尾追加

すなわち **1-step (テンプレをタップ → 全アクションが即座に末尾追加)** の設計だった。 PR #41 (2a1fc26) で当該挙動のまま実装され、 検証期間の実運用に投入された。

その後、 検証期間中のユーザー観測 (knockon#122 起票、 Graft POST 01KV743K774C4Y43XYD79DWSYM) で「テンプレ内の**一部アクションだけ**を採用したい」というシグナルが出た。 テンプレの粒度が「カテゴリ丸ごと」だと、 自前チェーンに不要なアクションまで混じり、 追加後に 1 件ずつ削除する運用になっていた (= 面倒さの再発)。

PR #137 (38d42ac、 knockon#122 / #133 / #134 統合) で PR-Y1 の挙動を改定する実装を投入した。 後続の PR #173 (b48f5aa、 knockon#168 / #155 follow-up) で picker が `TemplateChainPicker` (builtin) から `TemplateCategoryPicker` (新カテゴリカタログ / [ADR-0039](0039-catalog-restructure-modules-to-categories.md)) に置換されたが、 2-step 個別選択の**挙動そのものは継承**されている。

本 ADR は、 実装が先行して条文と乖離した状態を解消するために、 **ADR-0023 §想定される影響 (PR-Y1 範囲) の当該条文を書き換える判断**を明示化して残す ([K-005](../../KNOWLEDGE.md) — 影響を受ける ADR に逆参照を残す運用ルールの適用)。

## 検討した選択肢

- **案 A**: ADR-0023 を supersede する新規 ADR を起こす
- **案 B**: ADR-0023 §想定される影響を直接編集し、 判断ログを別途は起こさない
- **案 C**: 新規 ADR で「PR-Y1 §想定される影響のうち UI 動線条文のみを改定する部分変更」と明示し、 ADR-0023 側にも逆参照 1 行を残す (K-005 パターン)

## 決定

**案 C を採用**。

### 改定される条文 (ADR-0023 §想定される影響 §即時の影響 (PR-Y1 範囲))

- **旧**: 「テンプレ選択モーダル → 選択 → 各アクションを INSERT (新規 action として) + ノード末尾追加」
- **新**: 「テンプレ (カテゴリ) 選択モーダル → step1 でカテゴリを開く → step2 で個別アクションを checkbox で選択 (初期全選択 / 全選択・全解除 / 「N件を追加」ボタン) → 選択したアクションだけを新規 action として INSERT + ノード末尾追加」

### 変わらないこと (ADR-0023 の他の部分は維持)

- **PR-Y1 のスコープ境界**: schema 変更なし、 即着手可、 数時間規模 (実装済み)
- **PR-Y2 / PR-Y3 の計画**: サブチェーン本実装 + テンプレインポート (未着手・v1 検証で必要性判断)
- **サブチェーン data モデル (案 Q2)**: `actions.child_chain_id` 追加案は維持
- **テンプレ = builtin (コード内) スタート**: 新カテゴリカタログ ([ADR-0039](0039-catalog-restructure-modules-to-categories.md)) 経由で保持、 ユーザー追加可能化は非スコープのまま

## 理由

- **案 A (supersede) を捨てた理由**: PR-Y1 の目的 (テンプレから末尾追加で「一つのチェーンを作るのが面倒」を解消) と全体構造 (PR-Y1/Y2/Y3 の 3 段階、 サブチェーン data モデル、 テンプレ builtin スタート) は変わらない。 supersede すると系譜が「PR-Y1/Y2/Y3 全体が置き換わった」ように誤読される。 実際は動線条文の 1 箇所改定のみ。
- **案 B (直接編集のみ) を捨てた理由**: 判断ログを単体読みしても誤誘導されない状態を保つ (K-005) には、 「なぜ改定したか」を残す新規 ADR が必要。 直接編集だけでは「1-step から 2-step にした理由 (= 一部アクションだけ採用したいシグナル)」が失われる。
- **案 C を採用した理由**: [K-005](../../KNOWLEDGE.md) (「supersede しない部分変更」を片側リンクだけで処理した失敗) と [K-015](../../KNOWLEDGE.md) (先行 ADR の条文を軸別に拡張する運用) の両方に沿う。 影響を受ける ADR-0023 側に逆参照 1 行を残すことで、 ADR-0023 単体読みでも新 UI が動線条文と整合していることを辿れる。
- **2-step にした設計判断 (= 実装側の判断)**: step2 の初期状態を「全件選択」にすることで、 旧 1-step 利用者は「テンプレを開いてそのまま『N件を追加』」の 2 タップで同じ結果になる (摩擦の増分を最小化 / Augmentation 原則と整合)。 一部だけ採用したいユーザーは checkbox を外して部分追加できる。 両者を同じ動線で吸収する。

## 想定される影響

### 即時の影響

- ADR-0023 §想定される影響 §即時の影響 (PR-Y1 範囲) に本 ADR への逆参照 1 行を追記する (K-005 双方向リンク)
- SPEC.md / DESIGN-SYSTEM.md / CLAUDE.md への同期更新は不要 (SPEC は「テンプレから末尾追加」の抽象条文しか持たず、 動線 UI の詳細まで書いていない)
- コード側 (`src/TemplateCategoryPicker.tsx` / `src/useChainEdit.ts` / `src/ChainEditScreen.tsx`) は既に 2-step 実装済み (PR #137 + PR #173) — 本 ADR は back-fill

### 将来の覆すコスト

- **もう一度 1-step に戻す判断**: `TemplateCategoryPicker` の step2 をスキップして即 emit する分岐を追加すればよい。 UI コード 1 ファイル程度、 テストは step2 系を落として step1 系を新設。 挙動を「テンプレ選択で全件追加」に戻すだけなら 1 PR 規模。
- **step2 の初期選択状態を「0 件選択」に変える判断**: 実装 1 箇所の変更で済むが、 「旧 1-step 利用者にとって摩擦が増える」ため Augmentation 原則との整合を検討する。 別 ADR 案件。
- **PR-Y3 (テンプレインポート) 着手時の再確認**: PR-Y3 の「サブチェーン参照アクションを追加」動線は本 ADR とは別軸 (アクション個別選択ではなく、 チェーン単位のインポート)。 混同しないようにする。

### 注意点

- **[K-005](../../KNOWLEDGE.md) 適用**: ADR-0023 側に「§即時の影響 (PR-Y1 範囲) の動線条文は ADR-0046 により改定」の 1 行を追記する。 双方向リンクで系譜を辿れるようにする。
- **同 PR で更新するファイル**: 本 ADR (0046) 新規 + ADR-0023 逆参照 1 行のみ。 スコープ拡張禁止 (Issue #139 受け入れ条件と整合)。
- **後続 UI 変更で本 ADR が該当するか**: 「テンプレから追加」の動線をさらに変える判断が出たら、 本 ADR を supersede するか、 更に別 ADR で部分改定するかを判断する。 supersede の基準は「2-step 個別選択」の核が保たれるかどうか。
