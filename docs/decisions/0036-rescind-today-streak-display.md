# Today の連続達成日数 (streak) 表示を撤回し、反 streak をレンダリング層で貫く

## 文脈

Issue #103 で Today カード (チェーン単位) と ChainDetail ノード行 (アクション単位) に「N 日連続」を小さく表示する機能を出荷した。当時の起票者判断は「禁止 UI は『炎 / カレンダー型 / 警告色での未達アラート』であって、小さい数字での積み上がり表示は Celebrate (積み上がり) として許容する」というもの ([ADR-0004](./0004-design-direction-v02.md) の禁止条文を狭く解釈した)。

その後、分析タブを「ノード × 日付マトリクス」化する設計 (Issue #115) を詰める対話の中で、「streak を出すか」を改めて検討した。そこで `streak はまず無しで実機検証する` と決めた流れで、既に Today に漏れていた #103 の streak 表示との不整合が表面化した。分析面では streak を出さないのに Today では出ている、という状態は方針として一貫しない。

## 検討した選択肢

- **案A (採用): #103 の streak 表示を全面撤回する**
  - Today カード / ChainDetail ノード行の「N 日連続」を削除。派生関数 (`chainCompletionStreakDays` / `nodeCompletionStreakDays`) も他に利用箇所がないため削除。
- **却下: #103 をそのまま残す (現状維持)**
  - 「小さい数字なら Celebrate」という解釈を維持。だが分析面の方針 (streak 非表示) と矛盾し、反 streak の核がレンダリング層で崩れる。
- **却下: Today カードのチェーン単位 streak だけ残し、ノード単位だけ消す (部分残し)**
  - 「どの粒度なら許容か」の線引きが恣意的で、ガードレールが運用で揺れる。「数字 streak は出さない」と二値で決める方が一貫する。
- **却下: streak を「リセットしない緩い指標 (累積達成 / 30日達成率)」に置換する**
  - 反 streak の趣旨には沿うが、今は「まず無しで検証」フェーズ。物足りなさが観測されてから別 Issue で判断する (先送り)。

## 決定

案A を採用。Today から streak の数字表示を完全に外す。Today / 分析ビューとも、連続日数の数字・色強調は計算も表示もしない。達成の手応えは「積み上がる線 (スパイン)」と「定着 = 星 (★/☆、[Issue #118])」だけで作る。

具体:
- `ChainCard` の streak 表示・`streakDays` prop を削除
- `ChainDetail` ノード行の streak 表示・`nodeStreakDays` prop を削除 (定着の星 ★/☆ は維持)
- `TodayScreen` の prop 受け渡し、`useTodayData` の派生計算 (初期 + 楽観更新の再計算) を削除
- `domain` の `chainCompletionStreakDays` / `nodeCompletionStreakDays` を削除
- 関連テストを「streak を出さない」回帰テストに置換
- [SPEC.md](../../SPEC.md) §3 に撤回を反映

これは [ADR-0004](./0004-design-direction-v02.md) の「格子 / ヒートマップ / カレンダー型ストリーク / ストリーク炎 追加禁止」を **再確認**するもので、ADR-0004 を覆さない。#103 で導入した「小さい数字 streak は例外的に許容」という運用判断を撤回する位置づけ (#103 は ADR ではなく Issue 判断だったため、frontmatter の supersedes には載せず本文で明示する)。

## 理由

- **反 streak の核を守る**: 「小さい数字」でも streak は (1) 連続を煽り、(2) 切れた時にマイナスを指差す方向に働く。ADR-0004 が差別化の核として掲げた「マイナスを指差さない / streak 系プロダクトと差別化する」と直接衝突する。許容範囲を「数字の大小」で引くと境界が曖昧になり、ガードレールがレンダリング層で崩れる。
- **方針の一貫性**: 分析面 (Issue #115 の設計対話) で「streak はまず無しで検証」と決めた。Today だけ streak を残すと面ごとに方針がぶれる。
- **Augmentation 原則 (グローバル CLAUDE.md)**: 古典的 streak は「毎日続けろ」と人に要求する設計で、「人を変えず仕組みが吸収する」という Augmentation の逆。継続の手応えは「定着 = 星」という罰のない祝福で既に担保している。
- **死にコードを残さない**: 表示を消すだけでなく派生関数まで削るのは、唯一の利用面が Today だったため。中途半端に関数を残すと「いつか streak を出す」誘惑の温床になる。

トレードオフ:
- 連続日数による外的動機付け (損失回避) を v1 では持たない。これは意図した帰結。
- 将来「やはり継続の引力が弱い」と観測されたら、「リセットしない緩い指標」を別 Issue で再検討する余地は残す (本 ADR は数字 streak の不採用を決めるが、緩い代替指標まで永久に禁じるものではない)。
- **追記 (ADR-0041)**: 上記「却下: リセットしない緩い指標」を Issue #142 / [ADR-0041](./0041-cumulative-count-revision.md) で採択格上げした。 Today 見出し右に **アプリ全体の累計達成ノード数のみ** (`累計 N 個達成 (+今日M)`) を出す。 ノード単位の累計はノード行に持ち込まず分析ビューに集約 ([ADR-0041](./0041-cumulative-count-revision.md))。 本 ADR の「Today / 分析ビューとも連続日数の数字・色強調は出さない」(streak 系) は不変、 単純総和の累計は別物として両立。

## 一般原則: 失われうるか (+/-) 判定基準 (Issue #174 で追補)

本 ADR を「Today の数字 streak だけ撤回する個別判断」ではなく、Today / 分析 / 通知などレンダリング層全般で **数字・グリフ・ハイライトを載せるかどうか** を判定する一般原則として読み直す。判定軸は **「その指標は失われうるか (= 減る方向に動きうるか)」** の 1 軸。

- **失われない指標 (+) — 表示してよい**: 1 方向にしか進まない / 不可逆 / 「現在の状態」を示すクロス断面。
  - 例: 通算達成数 ([ADR-0041](./0041-cumulative-count-revision.md) `累計 N 個達成`)。
  - 例: 採用済み / 編集済み / 初達成済みの one-way フラグ (= 立ち上げチェックリスト #165 のマイルストーン群、 [src/onboardingChecklist.ts](../../src/onboardingChecklist.ts))。
  - 例: 「いま定着しているか」のクロス断面表示 (定着の星 `★`、[Issue #118](https://github.com/nokku-dev/knockon/issues/118))。塗り分けはせず常に塗りで出す (= 達成状態で薄めない、[DESIGN-SYSTEM.md](../../DESIGN-SYSTEM.md) §4.2)。
- **失われうる指標 (−) — 追加禁止**: 切れる / 減る / リセットしうる。マイナスを指差す方向に必ず働く。
  - 例: 連続日数 (本 ADR で撤回した streak 系の数字)。
  - 例: 直近 N 日達成率 / 比率指標 (分母固定の比率は未達で減る)。
  - 例: 未達アラート / 警告色での弱い指差し / 段階塗り率 (= 達成していないノードが半透明 = 弱い指差し)。
  - 例: 「達成=★ / 未達=☆」の塗り分け ([Issue #118] 追補で撤回した語彙、達成状態で表現が薄まる)。

グレーゾーン (= 数字を出していないが状態によって視覚的に減りうる表現) は **(−) 側に倒して見送る**。撤回コストは Phase 1 N=1 では極めて小さいので、迷ったら出さない方が反 streak / Celebrate 主の核を守れる。

この判定基準は [ADR-0004](./0004-design-direction-v02.md) §5 「禁止 UI (ハードガードレール)」の **抽出された一般原則** に当たる。ADR-0004 の個別禁止条文 (格子 / ヒートマップ / カレンダー型ストリーク / ストリーク炎 / 紙吹雪 / 弱い輪 / ドット塗り率の段階表現) はいずれも (−) 側の代表例である。

### 過去判断との対応関係

| 判断 / 表示要素 | +/- ラベル | 採否 |
|---|---|---|
| 連続日数 (本 ADR で撤回) | − 失われうる (連鎖切れで 0 リセット) | 不採用 |
| 累計 N 個達成 ([ADR-0041](./0041-cumulative-count-revision.md)) | + 単調増加 | 採用 |
| 定着の星 ★ (常に塗り、[Issue #118]) | + クロス断面・塗り分けしない | 採用 |
| 「達成=★ / 未達=☆」塗り分け ([Issue #118] 追補で撤回) | − 達成状態で薄まる | 不採用 |
| 立ち上げチェックリスト 5 マイルストーン (#165 / ADR-0042 P1) | + すべて one-way フラグ | 採用 |
| 達成マトリクス (Today 7D / 分析 60D、[ADR-0037](./0037-analytics-date-matrix.md) / [ADR-0038](./0038-today-chaindetail-7d-matrix-axis-reinterpretation.md)) | + 二値グリフ・連続強調なし | 採用 |
| 直近 N 日達成率 / 比率指標 (現時点未採用) | − 分母固定で未達日に減る | 不採用 |

レビュー観点: 数字 / グリフ / ハイライトを足す PR が来たら、上表に該当行が無いケースは新しい行として +/- ラベル付けして判断ログに残す (= 本 ADR の追補 or 新 ADR で supersede)。

[Issue #118]: https://github.com/nokku-dev/knockon/issues/118

## 想定される影響

- **覆すコスト (中)**: streak を再導入するなら派生関数の再実装 + UI 配線が要る。が、`Achievement` の正準データ ([ADR-0001](./0001-chain-data-model.md)) は不変なので、派生計算はいつでも復元可能。データ的な不可逆性はない。
- **スパイン / 定着の星 / 分析の達成率・折れ線は不変**: もともと streak 非依存。
- **実装レビューのガードレール更新**: 今後「Today / 分析に連続日数の数字を出す」提案は本 ADR で弾く。再導入したい場合は本 ADR を supersede する新 ADR が必要。
- **関連 Issue #115 (分析マトリクス)**: マトリクス上でも streak の数字・色強調は載せない、という前提を本 ADR が固定する。
- **追補 (#174)**: 上記「一般原則: 失われうるか (+/-) 判定基準」セクションを追加し、レビュー観点と過去判断対応表を本 ADR 内で機械的に参照できるようにした。`src/onboardingChecklist.ts` / `src/OnboardingChecklistCard.tsx` / `src/TodayScreen.tsx` のコードコメントが既に「ADR-0036 +/- 判定基準」と参照していた前提を、ADR 本文側で正規化した位置づけ ([SPEC.md](../../SPEC.md) §3 / [CLAUDE.md](../../CLAUDE.md) §4 / [KNOWLEDGE.md](../../KNOWLEDGE.md) K-038 と同期)。
- **追補 (ADR-0047)**: 分析タブの**達成率グラフ (= 比率)** を [ADR-0047](./0047-settlement-lifecycle-and-log-portfolio.md) で撤去し、定着ポートフォリオに組み替えた。達成率は本 ADR §一般原則の「(−) 失われうる指標 (比率)」に該当しており、撤去は本原則への収束 (潜在矛盾の解消)。定着ポートフォリオの主指標「定着 N 個」は単調増加 (+) で本判定軸に適合。
