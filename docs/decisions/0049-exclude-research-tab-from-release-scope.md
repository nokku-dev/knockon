# 研究 (メモ) タブを v1 リリーススコープから除外する (href: null で非表示・非破壊)

## 文脈

研究タブ (#175 / [ADR-0044](0044-research-manual-notes.md)) は当面「ユーザーの手動メモ一覧 + 右下 FAB」で、自動検出 (インサイト) は未実装。ADR-0047 でログ (定着ポートフォリオ) をリリースに載せた結果、現在の可視タブは **Today / チェーン / ログ / 研究** の 4 本。

リリースを絞る観点で見ると、研究タブはコア体験 (If-Then チェーン + Today) の外側にある。メモ一覧は「後から振り返る」補助機能で、prime objective (自分が毎日使う 1 本を最短で出荷) と完成判定 (Phase 1 = Today が実機で数日回る) の外。ユーザー判断で「研究タブはリリース段階では不要」となった。

## 検討した選択肢

- **案 A (採用)**: 研究タブを **タブバーから非表示 (`href: null`)** にし、`research.tsx` / メモ画面コード・`notes` データモデルは残す。
- **案 B**: 研究タブのコード・ルート・メモ UI を削除する。→ 再有効化時に作り直しコストが発生し、「後回し」ではなく「破棄」になる。
- **案 C (却下)**: 現状維持。研究タブをリリースに含めたまま出荷する。

## 決定

**案 A を採用。** `app/(tabs)/_layout.tsx` の研究タブ `Tabs.Screen` に `href: null` を付与し、タブバーから非表示にする。ルート・画面コード・`notes` データモデルは削除しない。

- リリース時の可視タブは **Today / チェーン / ログ の 3 本**。
- 出荷後に研究を再有効化するときは `href: null` を外す 1 行で戻せる (無移行)。
- **Today のアクション長押しによるメモ作成は残す** ([ADR-0044](0044-research-manual-notes.md))。メモは `notes` に保存され続けるが、一覧は研究タブ再有効化まで表示されない (書けるが見えない状態を許容する。データは失われないため、再有効化で全て見える)。
- 正準データ (`notes` 軸、[ADR-0044](0044-research-manual-notes.md)) は保存され続ける (派生の非表示化ではなく UI の非表示化。データ削除ではない)。

## 理由

- **非破壊 / 無移行の一貫性**: knockon のスコープ削除は「不要」ではなく「後回し」(SPEC §5)。UI を隠すだけで後から無移行で戻せる。ADR-0045 (分析タブ非表示) と同型のパターン。
- **リスクに触れる出荷を優先**: 完成判定は Phase 1 のコア体験 (Today)。研究 (メモ一覧) はコアの外。表面積を絞ってミニマルにリリースするほうが prime objective に直結する ([K-004](../../KNOWLEDGE.md) 「完成ゲートをコア体験に置く」の精神)。
- **ADR-0044 を supersede しない**: notes データモデル・Today 長押しメモ作成・`ON DELETE SET NULL` 等の 0044 の決定は維持される。覆すのは **研究タブをリリースに載せるというスコープ判断のみ**。よって部分改訂とし、双方向リンクで系譜を残す ([K-005](../../KNOWLEDGE.md))。

## 想定される影響

- `TabsLayout.test` で研究タブ `href: null` / 可視タブ 3 本を機械検証。
- SPEC §3 のタブ本数を 4 → 3 に同期。
- メモを書けるが一覧が見えないため、リリース中に大量のメモが溜まると再有効化時に一気に表示される。N=1 では問題なし。
