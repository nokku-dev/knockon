# Today アクション長押しからのメモ作成を無効化する (ADR-0049 の「書けるが読めない」状態を解消)

## 文脈

[ADR-0044](0044-research-manual-notes.md) で手動メモを導入し、作成導線を **2 つ**用意した。

1. 研究タブの右下 FAB（一覧 + 作成）
2. Today のアクション長押し（対象ノード自動選択）

その後 [ADR-0049](0049-exclude-research-tab-from-release-scope.md) で研究タブを v1 リリーススコープから除外した（`href: null`）。このとき **Today の長押しメモ作成は残す**判断をし、影響を次のように書いた。

> メモは `notes` に保存され続けるが、一覧は研究タブ再有効化まで表示されない（**書けるが見えない**状態を許容する。データは失われないため、再有効化で全て見える）

**実機確認でこの判断が誤りだったと分かった**（2026-07-30・Taku 判断）。書いたメモをどこからも読めない状態は、データが失われないかどうかとは別に、**長押しでメモが書けること自体が混乱の原因**になる。ユーザーから見れば「書いたものが消えた」と区別がつかない。

## 検討した選択肢

- **案 A (採用)**: Today の長押しメモ作成を**無効化**する。`notes` データモデル・`NoteComposeModal` / `ResearchScreen` / `useNotesData` は残置。
- **案 B**: 研究タブを再有効化して読めるようにする（ADR-0049 を反転）。→ リリースの表面積を絞る判断（ADR-0045 / 0049）に逆行する。メモ一覧はコア体験（Today + チェーン）の外側で、自動インサイトも未実装のまま。
- **案 C**: メモ関連のコード（`NoteComposeModal` / `ResearchScreen` / `notes` テーブル）を削除する。→ 再有効化時に作り直しコストが発生し、SPEC §5 の「削った機能は不要ではなく**後回し**」に反する。ADR-0052（Notion 撤去）とは違い、こちらは**戻す前提がある**。
- **案 D**: 長押し自体を無効化する。→ 定着ノードの長押しメニュー（[ADR-0047](0047-settlement-lifecycle-and-log-portfolio.md) の「定着を取り下げる」）を殺してしまう。取り下げは本人だけが行える唯一の導線なので不可。

## 決定

**案 A を採用。** `app/(tabs)/index.tsx` から `TodayScreen` への **`onAddNote` prop を渡さない**。

- `TodayScreen` / `ChainDetail` は `onAddNote` 未指定なら長押しメモ動線と `NoteComposeModal` を描画しない**スイッチ式**で実装されていたため、無効化は **prop を 1 つ渡さないだけ**で済む（[ADR-0045](0045-exclude-analytics-tab-from-release-scope.md) / [ADR-0049](0049-exclude-research-tab-from-release-scope.md) の `href: null` と同型の非破壊パターン）。
- **定着ノードの長押しメニューは残る。** `makeNodeLongPress` はメモ導線が無ければ「定着を取り下げる」専用の Alert を出す。長押しを殺したのではなく、メニューからメモの選択肢が消える。
- 研究タブを再有効化する判断をしたときは、`onAddNote={handleAddNote}` を戻す 1 行で復帰する。
- 回帰は `src/todayMemoDisabled.test.ts` で機械検証（[K-006](../../KNOWLEDGE.md) 同型）。「prop を渡していない」「メモ関連コードが残置されている」「取り下げ導線が生きている」の 3 点を固定した。

## 理由

- **「書けるが読めない」は許容できない**。ADR-0049 はデータ保全（失われない）を根拠にこれを許容したが、**ユーザーから見た体験はデータの保全状況と独立**である。書いたものが見えなければ「消えた」と区別できない。データ保全は必要条件で、十分条件ではなかった。
- **読み書きは同じスコープ判断に従うべき**。片方だけ残す形は、スコープを絞る意図（ADR-0045 / 0049）に対して中途半端だった。ADR-0049 を否定するのではなく、**その適用を読み書き両方に揃える**改訂。
- **非破壊を維持できる**。案 C（削除）を採らないのは、ADR-0052（Notion 撤去）と違って**戻す前提があるから**。研究タブは「不要」ではなく「後回し」で、自動インサイトを実装する判断が立てば復帰する。同じ「隠す」でも前提が違う。
- **取り下げ導線を守る必要がある**。ADR-0047 の「システムは降格させない、本人だけが取り下げる」を成立させる唯一の UI が定着ノードの長押しメニュー。メモを消す作業でこれを壊すのが最大のリスクだったため、テストで固定した。

## 想定される影響

- **[ADR-0044](0044-research-manual-notes.md)**: メモのデータモデル（`node_id` 単一 nullable / `ON DELETE SET NULL`）・`ResearchScreen` の仕様は維持。覆るのは **「Today アクション長押しからの作成」という導線の 1 つ**のみ。部分改訂とし双方向リンクを残す（[K-005](../../KNOWLEDGE.md)）。
- **[ADR-0049](0049-exclude-research-tab-from-release-scope.md)**: 「Today のアクション長押しによるメモ作成は残す」条項を本 ADR で撤回。同 ADR の「書けるが見えない状態を許容する」も撤回する。研究タブを `href: null` にする判断自体は維持。
- **[ADR-0047](0047-settlement-lifecycle-and-log-portfolio.md)**: 定着取り下げの長押しメニューは無影響。ただし Alert の選択肢が「メモを追加 / 定着を取り下げる」から「定着を取り下げる」のみに変わる。
- **既存の `notes` 行は削除しない**。書き込まれたメモは残り、研究タブ再有効化時に表示される。
- **覆すコスト (低)**: `onAddNote={handleAddNote}` を戻す 1 行 + `todayMemoDisabled.test.ts` の削除。
- SPEC §3 の研究タブ記述に「Today 長押しの作成導線も無効」を同期する。
