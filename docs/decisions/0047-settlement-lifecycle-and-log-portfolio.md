# 定着ライフサイクル再設計 — ログ画面を「達成率」から「定着ポートフォリオ」へ組み替え、定着=生涯マイルストーン化・取り下げ事実軸を追加 (v1 出荷前に取り込み・ADR-0045 反転)

## 文脈

リリース直前に、まずマネタイズ (サブスク導入是非) を検討する過程で、無料で提供する分析ビューの窓 (60D マトリクス / 14D 達成率) の妥当性を見直した。そこから「そもそも**達成率 (= ルーティンの何割を達成したか)** に意味があるのか」という違和感に到達した。

- 達成率は **比率**であり、[ADR-0036 §一般原則](0036-rescind-today-streak-display.md) が「追加禁止の (−) 失われうる指標」として名指ししているもの (「連続日数 / **比率** / 段階塗り率 / 達成状態反映の塗り分け」)。反 streak / Celebrate 主 ([ADR-0004](0004-design-direction-v02.md) §決定 5 / DESIGN-SYSTEM §0) と構造的に逆。つまり達成率ビューは、後から確立した ADR-0036 の原則と**潜在的に矛盾**したまま実装されていた ([ADR-0024](0024-goal-view-analytics-phase-3-unified.md) の分析実装が先行していた名残)。
- ユーザーが本当に見たいのは「ルーティンの何割達成したか」ではなく、**「いくつ定着させられているか / いくつ育てている途中か / どれが定着していて、どれが定着していないか」**。これは各ノードを**育成ステージに分類して見渡す**という単一の認知目的に畳める。現在のログ画面 (60D マトリクス俯瞰 + 14D 達成率 + メトリクス身体指標) は複数目的が混在しており (失敗パターン検知ルール §3「1 画面に複数の認知目的」)、定着を軸に単一目的へ絞る好機。

あわせて、既存の定着判定 (`isNodeEstablished`, 14D 中 10 日以上 = 定着 → ★) は **14D ローリング窓**で、お休みすると ★ が消える = 失われうる (−) 指標だった。定着を「積み上がりの祝福」として扱うなら、この (−) 性を解消する必要がある。

本判断は Today (出荷面) の挙動変更・新しい正準データ軸・ログ画面 IA 再設計を含む純増スコープだが、ユーザーは「出荷前にやり切りたい」と判断し **v1 リリースに取り込む**。これに伴い [ADR-0045](0045-exclude-analytics-tab-from-release-scope.md) の「分析 (ログ) タブを非表示」を反転する。

## 検討した選択肢

### 定着の定義
- **案 A (採用): 生涯マイルストーン (latch)**。一度定着バーに到達したら永続。単調増加 (+)。「いくつ定着させられたか」が増える一方で、システムはスリップを指差さない。
- **案 B (却下): 現在の一貫性 (rolling)**。直近 14D≥10 を満たす間だけ定着。今どれが生きているかは正確だが、お休みすると ★ が消える (−)。達成率と同じマイナス指差しが復活するため却下。
- **案 C (却下): ハイブリッド (バッジ永続 + 現状併記)**。「今は継続していない」がソフトなマイナス表現になりうるため却下。

### 定着ステータスの保存
- **案 A (採用): 保存しない (派生のまま)**。過去は書き換わらないため「取り下げ以降に、実タップで定着バーを満たした窓が存在するか」を履歴スキャンで派生でき、それ自体が単調増加。CLAUDE.md §正準データの「定着判定は保存せず表示時に派生」ガードレールを維持。
- **却下: 定着ステータスをカラムで保存**。派生値の非正規化 = ガードレール違反。

### 自動達成 (定着ノードを Today でタップ不要にする) の実装
- **案 A (採用): ハイブリッド (表示層で定着バンド)**。達成レコードは書かない (「保存は事実」厳守・[K-002](../../KNOWLEDGE.md))。60D マトリクスは定着後を表示層で「定着バンド」として**派生描画**し、見た目のスカスカを回避。マトリクスの意味は「実行」から「実行 + 定着状態」の 2 層になる。
- **案 B (却下): source タグ付きで auto 達成レコードを自動生成** (`source: 'auto'`, [ADR-0026](0026-metric-kinds-customization.md) のメトリクス source 前例)。累計・マトリクスは埋まり続けるが、正準データに auto が混ざり、累計に数えるか別途判断が要り複雑度が増す。
- **案 C (却下): 表示だけ (定着バンドも塗らない)**。honest だが 60D マトリクスが定着後スカスカに見える。

### スコープ
- **案 A (採用): v1 出荷前に取り込む**。定着ポートフォリオが本アプリの感情的ペイオフの核であり、これを含めて完成と判断。
- **案 B (却下): fast-follow (出荷後の第 1 機能)**。正準データ設計により後付け移行コストがほぼゼロなので技術的には妥当だったが、ユーザーが「やり切ってから出荷」を選択。

### マネタイズ (本 ADR の起点だが別 ADR に分離)
- 無料出荷・サブスク先送り (SPEC §5 維持) を決定。将来ゲートは「retention 短縮」でなく「分析ビューの窓を無料ベースラインの外側へ拡張」。正準データは常に全期間保存。→ 別途 ADR で記録予定 (本 ADR の付随ではなく独立したスコープ判断のため)。

## 決定

**定着を生涯マイルストーン (latch・派生) に再定義し、ログ画面を「定着ポートフォリオ」へ組み替える。v1 リリースに取り込み、ADR-0045 を反転する。**

1. **達成率グラフを撤去** (比率 = ADR-0036 (−) 禁則に収束)。
2. **定着ステージ (ノード単位・ゆるい連鎖判定と一貫)**:
   - これから: 実タップ達成 0
   - 育成中: 実タップ達成 ≥1・定着バー未到達
   - 定着: 「**取り下げ以降**に、実タップで定着バー (当面 14D 中 10 日) を満たした窓が存在」(latch・派生)
3. **保存する正準データは 1 軸だけ増やす**: **定着取り下げ `(node_id, retracted_at)`** = ユーザーが「最近やれてない」と感じたときに定着を取り下げる観測事実 ([ADR-0012](0012-anchor-firing-events.md) / [ADR-0044](0044-research-manual-notes.md) と同型・[K-015](../../KNOWLEDGE.md))。定着ステータス自体は保存しない。
4. **Today**: 定着ノードは ✓(自動) 表示・タップ不要 (達成扱いは定着ステータス由来、**達成レコードは書かない**)。育成中/これからは従来どおり手タップ。「取り下げ」導線 (長押し等、配置は別途) で育成中へ戻し、再タップ運用で再定着可能。**システムは降格させない、本人だけが取り下げる**。

   > **追補 (2026-07-06・#205 実装時のユーザー判断)**: **「✓自動表示・タップ不要 (= auto 達成)」を撤回**し、定着ノードも**タップは従来どおり有効**とする。定着の可視化はアクション名の右の小さな **★** のみ (DESIGN-SYSTEM §4.2 の既存機構) に集約し、auto 達成 (レコード非書込の表示上 ✓) は実装しない。理由: (a) タップ運用を残すことで達成の判断権をユーザーに残す (Augmentation / 本人が主語)、(b) 「表示は ✓ だが手動でも動かせる」は marker/spine の二重解釈を生み UX が濁る。K-002 (auto 達成レコードを書かない) は「そもそも auto 達成しない」ことで自明に満たされる。**取り下げ導線は「定着ノードの長押しメニュー (メモを追加 / 定着を取り下げる) + ログ画面の定着ポートフォリオ」の両方**に確定 (配置未定を解消)。60D マトリクスの定着バンド (§決定5) は表示層派生描画として存置 (本追補の影響外)。SPEC §2 / CLAUDE.md §1 / understanding-map と同期。

   > **追補 (2026-07-07・#205 再判断)**: 上記 07-06 の撤回を **再反転** し、**auto-✓・タップ不要を採用する** (= 本 ADR 当初の §決定4 に回帰)。理由: 実運用で「チェーンにアクションを繋いで増やすほど、毎日のタップ記録の手間が線形に増える」という摩擦が主問題として顕在化。定着したノードは「もう身についた＝手を離せる」べきで、毎日タップさせるのは Augmentation (人に負担を課さない) に反する。**設計**: 定着ノードは Today で表示上の達成 (effective = 実レコード OR 定着 latch) を ✓ とし、スパインの伸び・マーカーの塗り・✓ を effective 値で描く。**タップは no-op** (達成レコードを書かない = K-002 は依然自明に成立)。長押しメニュー (メモ / 取り下げ) は引き続き有効。07-06 の懸念 (b)「marker/spine の二重解釈」は「タップを no-op にして常に auto-✓ に倒す (手動トグルを残さない)」ことで解消 (= 二重解釈が生じない)。累計・60D マトリクスへの反映は「派生で数える」(レコード非書込のまま effective で集計・別 PR)。SPEC §2 / CLAUDE.md §1 / understanding-map と同期。
5. **60D マトリクス**: 存置。定着後を表示層で「定着バンド」として派生描画 (レコード非生成)。
6. **ログ画面 = 定着ポートフォリオ**: 上部に「定着 N・育成中 M」カウント (単調増加の Celebrate 主役)、本体はステージ別グルーピング一覧。メトリクス節 (身体指標) は別軸で存置。
7. **ADR-0045 を反転**: ログ (分析) タブの `href: null` を外し v1 リリースに表示。率でなく定着ポートフォリオになったことで、リリースに載せる価値が生まれた。

> **追補 (2026-07-07・#205 ステージ細分化 + 週次流入)**: 育成中と定着の間に「**もう少しで定着**」ステージ (§決定2) を追加し、ステージを **これから / 育成中 / もう少しで定着 / 定着** の 4 段にする。もう少しで定着 = 現在の 14D 窓 (取り下げ以降・今日以前) で eligible 達成が **8〜9 日** (定着バー 10 日の直前 2 日、ユーザー判断)。10 日以上なら定着 (latch) 側。ログ画面 (§決定6) 上部に「定着 N・もう少しで定着 P・育成中 M」カウント (クロス断面) と、その下に「**今週の流入**」= 先週 (7 日前) から定着 / もう少しで定着へ**上方向に移動した個数** (`定着入り +X・もう少しで定着入り +Y`) を出す。増減 (net) ではなく流入のみ・降格は数えない (マイナスを指差さない)。両方 0 の週は非表示。純粋関数 `nodeSettlementStage` / `countSettlementStages` / `settlementStageMovements` (domain・import ゼロ K-007) で派生。SPEC §2 / §3 同期。

## 理由

- **原則への収束であって寄り道ではない**: 達成率 = 比率 = ADR-0036 の (−) 禁則。撤去は分析タブを ADR-0036 の原則に整合させ、潜在矛盾を解消する。ユーザーの「率は意味あるのか」という違和感は、プロダクト原則が実装の不整合を検知したもの。
- **latch + 取り下げが Augmentation を完成させる**: システムは絶対に降格させない (マイナスを指差さない)。習慣を根付かせたご褒美 = 毎日タップから卒業できる (摩擦を減らす)。それでも「落ちた」の判断権はユーザーが握る。「システムが咎める」でなく「本人が選ぶ」= CLAUDE.md §Augmentation 原則の核。
- **ガードレールを 1 つも破らない**: latch は履歴の不変性から派生で単調増加になるため、定着判定は派生のまま (保存禁止を維持)。増える保存は「取り下げ」という観測事実 1 軸だけ = ADR-0012/0044 と同じ「派生値ではなく事実軸を足す」パターン。auto 達成レコードを書かないことで「保存は事実」(K-002) も厳守。
- **Celebrate の主役移動**: 累計達成 N 個 ([ADR-0041](0041-cumulative-count-revision.md)・実タップベース) は維持しつつ、ポートフォリオでは「定着 N 個」が主役。両方とも単調増加 (+) で ADR-0036 の判定軸に適合。
- **出荷前取り込みの正当化**: これを含めて初めて「毎日使う 1 本」の感情的ペイオフが閉じる、というユーザー判断。移行コストは取り下げ軸の追加のみで小さい。
