# チェーン 1 本時の discovery ナッジを削除する（#166 revert）

## 文脈

Issue #166 で、採用チェーンが**ちょうど 1 本**のとき Today 下部に
「もう一本、テンプレートから足す」discovery ナッジを出す実装を入れた（PR #172）。
コード上は「ADR-0042 採択」とタグ付けされていたが、ADR-0042 の実体は夜サマリ通知
（#169）であり、本ナッジは別提案由来の緩いタグだった。

リリース後に前提を見直したところ、次の違和感が出た:

- **チェーンを増やすのは本来かなり長期のマイルストーン**。1 本目を定着させている
  最中のユーザーに 2 本目を訴求するのは早すぎる。
- knockon の基本原則（Augmentation = 既存フローに無理なく乗せる・人に努力や行動の
  追加を要求しない / 反 streak・マイナスを指差さない）と、1 本時に「もう一本」を
  指し示すナッジはトーンがズレる。

## 検討した選択肢

- **案 A**: ナッジを削除する（#166 を revert）。
- **案 B**: 発火条件を変える（「1 本目が十分定着してから」「連続達成 N 回後」等）。
- **案 C**: 据え置き（マージ済みのまま判断保留）。

## 決定

**案 A（削除 / revert）** を採用。`f207481`（PR #172）を revert し、`onOpenDiscovery`
prop・1 本時ナッジ JSX・専用 style・関連テストを除去（PR #178）。#176 オンボーディング
チェックリスト・#175 の隣接変更は保持。

## 理由

- 発見導線 `/discover`（DiscoveryIndexScreen, ADR-0039）は**チェーンタブから常設で
  到達できる**。Today の 1 本時ナッジを外しても、新チェーンを探す機能そのものの
  発見性は損なわれない。失うのは「Today からの 1 本時だけの近道」のみ。
- 「1 本 → もう 1 本」という訴求の前提（チェーン増を短期で促す）が、チェーン増は
  長期マイルストーンという実態と合っていない。間違った前提のナッジを残すより、
  常設導線（/discover）に委ねる方が原則と整合する。
- 案 B（条件変更）は「いつ定着とみなすか」の閾値設計が必要で、その閾値自体が
  未検証。まず削除し、必要が出てから別の入口/タイミングを設計する方が安全
  （過剰実装を避ける）。

## 想定される影響

- Today から discovery への近道が無くなる。新チェーン採用は当面チェーンタブ →
  /discover を主動線とする。
- 後で「チェーン増を促す導線」が必要になった場合は、本 ADR を踏まえ、
  1 本時ではなく「1 本目が定着した」シグナル（連続達成・経過日数等）を起点に
  設計し直す（案 B の再検討）。覆すコストは小さい（ナッジ再追加は局所的）。
- ADR-0042（夜サマリ通知 #169）は無関係であり本 ADR の影響を受けない。
