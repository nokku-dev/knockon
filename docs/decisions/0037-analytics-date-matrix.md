# 分析タブの「日々の記録」を日付チップ列 → ノード × 日付の達成マトリクスにし、禁止 UI を二値マトリクスに限り再解釈する

## 文脈

Issue #115: 分析タブの達成アクションのリストを「日付タブで 1 日ずつ切り替える」現状 ([ADR-0034](./0034-analytics-daily-detail-view.md) / `DayDetailSection`) から、**複数日を一度に俯瞰できる表現**にしたい。要件は「縦 = アクション、横 = 日付、既定は最新、横スクロールで過去 2 ヶ月」。

これは「縦アクション × 横日付」という構造上、[ADR-0004](./0004-design-direction-v02.md) / [DESIGN-SYSTEM.md §0](../../DESIGN-SYSTEM.md) の **禁止 UI「格子 / ヒートマップ追加禁止」** に字面で触れる。禁止ルールを分析面に限って緩めるのか、原則を貫いて別案で吸収するのかの意思決定が必要だった。あわせて、設計対話の中で「streak はまず無しで検証」「セルは塗り四角・二値」と方針を確定した ([ADR-0036](./0036-rescind-today-streak-display.md) で Today の streak も撤回済み)。

## 検討した選択肢

- **Option A (却下): GitHub commit graph 風ヒートマップ** — セルを達成度に応じた段階色 (淡→濃) で塗る。直感的だが「ドット塗り率の段階表現禁止」「ヒートマップ禁止」を**直接**破り、ADR-0004 を全面 supersede する必要がある。マイナスを指差さない核と整合しない。
- **Option B (採用): 達成グリフ/塗り四角マトリクス (二値)** — セルは塗り四角の**二値** (達成 = 塗り / 未達 = 極淡アウトライン / 休む日 = 空)。段階色・赤・連続強調を持たない。チェーン単位でグループ化。
- **Option C (却下フォールバック): 分析タブに触れず、チェーン詳細に複数日テープを足す** — 禁止 UI に最も忠実だが、Issue が指定する「分析タブで俯瞰」を満たさない。

セル表現の中では「✓/○ グリフ維持」も検討したが、ユーザー判断で「四角を塗る気持ちよさが継続に効く」ため**塗り四角**を採用した。

## 決定

Option B (塗り四角・二値マトリクス) を採用する。

- **データ (純粋・派生のみ)**: `analyticsDerivation.ts` に `dateMatrixForWindow(windowDates, chains, actionsById, achievements)` を追加。日付ごとに `resolveActionForDate` で variant 解決し `{date, achieved, skipped}` のセルを返す。正準データ ([ADR-0001](./0001-chain-data-model.md)) は不変、保存しない。
- **hook**: `useDateMatrix` (60 日窓を 1 範囲クエリでロード)。`useDayDetail` とは責務分離 (マトリクス / 1 日詳細)。
- **UI**: `DateMatrixSection` — 左固定ラベル列 (チェーン名 + ノード名) + 右横スクロール (日付列、初期位置 = 右端 = 最新)。セル配色は二値:
  - 達成 = `COLOR_GROW` で塗った四角 (唯一の「塗り」= Celebrate 主)
  - 未達 (対象日) = `COLOR_LINE_BG` の極淡アウトライン四角 (赤を使わない = マイナスを指差さない)
  - 休む日 (variant null) = 空セル
  - 連続日数の数字・色強調は持たない (反 streak)
- **インタラクション**: セルタップ → その日を選択し、`DayDetailSection`（`showDateSelector={false}`）を**マトリクス直下にインライン表示** (ADR-0034 の 1 日詳細を捨てずに内包)。
- **窓**: 分析面の本 UI のみ 60 日 (8 週)。Today / チェーン詳細の窓は 14D 維持 (SPEC §3 の例外)。
- 単独の日付チップ列 (ADR-0034) は分析タブから**廃止**し、マトリクスがその役割を引き継ぐ (`DayDetailSection` 自体はチップなしモードで存続)。

### 禁止 UI の再解釈 (K-015 同型の軸別再解釈)

ADR-0004 / DESIGN-SYSTEM §0/§5 / CLAUDE.md の「格子 / ヒートマップ追加禁止」は **supersede しない**。禁止条文の趣旨は「**段階塗り率 / 赤色での未達アラート / streak 強調による連続煽り**」であり、それを持たない二値マトリクスは対象外、と軸別に再解釈する。各禁止条文に「ただし分析面の二値マトリクス (ADR-0037) は対象外」と逆参照注記を足す。

## 理由

- **Issue の核 (俯瞰したい・タブ切替したくない) を最小形で満たす**。
- **反 streak / Celebrate 主を保てる**: 二値・赤なし・連続強調なしなので、禁止の核 (マイナスを指差さない) を割らない。「塗る気持ちよさ」は達成セルの塗りで得つつ、未達は極淡で煽らない。
- **派生のみ / 正準データ不変**: 既存の `resolveActionForDate` / `isNodeAchievedOn` を日付ループで使うだけ。スキーマ変更なし、新規クエリは既存 `listAchievementsForNodes` の範囲指定で足りる。
- **過去判断を捨てない**: ADR-0034 の 1 日詳細はドリルダウン先として内包。移行コストなし。
- ボトムシートではなく**インライン詳細**にしたのは、分析タブが縦スクロール 1 枚で完結する構造を保つため (gorhom BottomSheet 追加の複雑さ・テスト摩擦を避ける)。提案のボトムシート案からの逸脱だが UX は同等。

トレードオフ:
- **禁止 UI の字面を一度触る** (= 再解釈の運用負荷)。境界は「段階塗り率/赤/streak 強調を持つか」で引く。
- **SPEC §3「v1 単一窓 14D 固定」を分析面 1 セクションだけ 60 日に拡張**。
- **連続が目視で見える**ことが反 streak と矛盾の種になりうる。数字/色で強調しない運用ルールで抑える。煽りに感じたら未達セルをさらに弱める / 週セパレータ調整 (Phase 1 監視シグナル)。
- a11y: 数百セルの label 設計コスト。

## 想定される影響

- **覆すコスト (低〜中)**: 派生のみなのでマトリクスを外しても正準データに影響なし。窓を 14D に戻すのも定数変更。
- **多チェーン化 (R1)**: 10+ チェーン × ノードでスクロール体験が悪化したら、チェーングループ折りたたみを Phase 2 で判断。
- **描画 (R)**: 現状はプレーン `<View>` セル。N=1 (〜数百セル) で体感問題なし。セル数が増えたら `react-native-svg` の rect 一括描画に置換する判断トリガー。
- **アンカー発火の併記 (R5)**: Issue 範囲外。将来マトリクスに発火行を淡く足す余地はあるが v1 非スコープ。
