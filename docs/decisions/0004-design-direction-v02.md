# デザイン方針を v0.2（モダン・ミニマル / ダーク既定 / 伸びる線が主役 / Celebrate 主）へ転換し、「弱い輪」を v1 から廃止する

## 文脈

knockon は If-Then / habit stacking の差別化を「streak（行為の連続）の対極」に置く。`Augmentation not Transformation` の原則に従い、煽らない・マイナスを指差さない・積み上がりだけを可視化する（[SPEC.md](../../SPEC.md) §1）。

初期のデザイン方針 v0「Quiet Ink」（紙・インク・editorial、Fraunces セリフ、淡い格子と弱い輪の指差し）は「使い込むほど壁に貼られた絵のように馴染む」を狙ったが、参照実装を毎日触る前提で見直すと、**日々の高揚に欠ける / 達成のセレブレーション要素が弱い / 弱い輪のアラート的表現が Celebrate 主と矛盾** という三点が表面化した。prime objective は「自分が毎日使う 1 本を最短で完成・出荷する」（[CLAUDE.md](../../CLAUDE.md)）であり、毎日触って気分が上がらないトーンは prime objective に直接効く。

加えて [KNOWLEDGE.md](../../KNOWLEDGE.md) K-003 で、コアモデルが固まる前に UI を精密化すると作り直しが多発する失敗を確認済み。データモデルは [ADR-0001](./0001-chain-data-model.md) で確定したので、ここでデザイン方針の上位レイヤー（トーン・主役要素・禁止表現）だけを ADR として固定し、トークン値や個別画面の v0.2 化は実装の中で変更前提とする。

## 検討した選択肢

- **案A（採用）**: v0.2 へ転換。**モダン・ミニマルツール / ダーク既定 / 「起点アンカーから下へ流れる 1 本の連続スパインが主役」/ 達成 = 線が伸びる / 形変化は「定着で円→星」の 1 回のみ / accent は「今日発火中」と「ノック」だけ / star は定着到達時のみ**。同時に **「弱い輪」を v1 から廃止**（マイナスの可視化を持たない）。格子・ヒートマップ・ストリーク炎・紙吹雪・弱い輪の指差し表示は **追加禁止**（ハードガードレール）。
- **案B（却下）**: v0 の Quiet Ink（紙・インク・editorial・Fraunces）方向を維持する。
- **案C（却下）**: v1 でも「弱い輪」を残し、未達・連鎖切れに近い箇所を淡く可視化する。
- **案D（却下）**: 達成度をドット塗り率の段階表現（0% → 30% → 60% → 100%）で見せ、定着の手応えをグラデーションで作る。

## 決定

案A を採用する。具体的に以下を不変条件として固定する:

1. **トーン**: モダン・ミニマルツール。ダーク既定（Light も常時提供）。セリフ書体は使わず、欧文サンセリフ＋和文サンセリフで統一。
2. **主役**: チェーン = 起点アンカーから下へ流れる **1 本の連続スパイン**。達成 = 線が一段スッと伸びる（モーション 1 種のみ）。
3. **Celebrate 主**: マイナスを指差さない。形変化は **「円 → 星」の 1 回のみ**（単独アクション定着 = 塗り星 / サブチェーン一部未達・親では達成扱い = 白抜き星）。**注: 白抜き星はサブチェーン参照の存在を前提とする表現で、サブチェーンが v1 非スコープ化された [ADR-0006](./0006-phase1-completion-and-scope-narrowing.md) により v1 実装からは外れる**（デザイン方針の核は維持・将来サブチェーン復活時に再導入）。
4. **色の規律**: accent（赤系）は「今日発火中」と「ノック」だけ、star（黄系）は定着到達時だけ。線は `--grow`（ニュートラル明色）で伸ばす。生 hex / px の直書き禁止（トークン経由）。
5. **禁止 UI（ハードガードレール）**: 格子 / ヒートマップ / カレンダー型ストリーク / ストリーク炎 / 紙吹雪 / **弱い輪の指差し表示** / ドット塗り率の段階表現 を追加禁止。
6. **スコープ**: 「弱い輪」は v1 非スコープ（[SPEC.md](../../SPEC.md) §5）。後続レイヤーでの再導入を検討する場合は本 ADR を supersede する新規 ADR を作る。

トークン値（カラー / 余白 / 角丸）・タイポグラフィの具体実装書体・個別画面のレイアウトは **変更前提**。本 ADR の対象は方針レイヤー（トーン・主役・禁止表現）のみ。詳細は [DESIGN-SYSTEM.md](../../DESIGN-SYSTEM.md) を参照。

## 理由

- **prime objective との整合**: 「自分が毎日使う 1 本」を最短で完成させるには、毎日触って高揚するトーンが必要。v0 の壁的トーン（案B）は「使い込むほど馴染む」狙いだが、初日からの引力に欠ける。
- **差別化（反 streak）の核を守る**: 案C の弱い輪と案D のドット塗り率段階表現は、どちらも「未達・連鎖切れの近接」を可視化する方向で、Celebrate 主と直接衝突する。streak 系プロダクトと差別化するためには、**マイナスを指差さない** ことを表現レイヤーでハードガードレール化する必要がある。データモデル（[ADR-0001](./0001-chain-data-model.md)）と連鎖判定（[ADR-0002](./0002-loose-chain-judgement.md)）でゆるさを担保しても、UI 側で厳密 streak 的な表現を許すと差別化がレンダリング層で崩れる。
- **形変化を 1 回に絞る心理効果**: 達成のセレブレーションを濫用すると効きが鈍る。「円 → 星」を定着の唯一の形変化に絞ることで、定着の手応えを希少資源として保つ。案D のグラデーション表現は形変化の頻度を上げ、アラート的になる（達成していないノードが「半分塗り」で表示されるのは弱い指差し）。
- **K-003 を踏まえた書き分け**: 方針（不変）と詳細（変更前提）を ADR とドキュメント側で分離する。本 ADR は方針の固定だけを担い、DESIGN-SYSTEM.md 側のトークン値や書体選定は実装フィードバックで動かしてよい。

トレードオフ:
- 「弱い輪」を可視化する将来パス（未達の認知 → 改善行動への誘導）を v1 では持たない。これは Celebrate 主の意図的な帰結。
- ダーク既定にすることで、屋外・強い光環境での視認性が Light テーマ依存になる（Light は常時提供で吸収）。
- 形変化を 1 回に絞ることで、定着以外の節目（初回達成・連続実行 N 回など）に対する視覚的祝福手段が減る。これは「streak の節目を祝う」誘惑を抑える側に倒した結果。

## 想定される影響

- **ハードガードレールの運用**: 実装レビューで以下を弾く。
  - 格子・ヒートマップ・カレンダー型ストリーク・ストリーク炎・紙吹雪・弱い輪の指差し表示・ドット塗り率の段階表現の追加。
  - accent / star の用途拡張（「今日発火中」「ノック」「定着」以外への流用）。
  - セリフ書体の導入・生 hex / px の直書き。
  - 「円 → 星」以外の形変化追加。
- **既存資産への波及**: 参照実装 `/reference/today.html` は v0.1 のままで v0.2 化が未了（[DESIGN-SYSTEM.md](../../DESIGN-SYSTEM.md) §0）。参照アプリは出荷物ではないので、必要になった時点で v0.2 化すればよく、本 ADR では強制しない。
- **後で覆すコスト**: 方針レイヤーの転換なので、覆す場合は新規 ADR で本 ADR を `supersedes` に指定する。トークン値の調整・書体差し替え・個別画面のレイアウト変更は本 ADR を覆さずに実施可能（変更前提のレイヤー）。
- **「弱い輪」復活の手順**: v1 出荷後に「弱い輪」相当の表現を再検討する場合、本 ADR を supersede する新規 ADR を作り、Celebrate 主との両立方法（指差しではない見せ方）を明示する。
