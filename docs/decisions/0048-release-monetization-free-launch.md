# リリース時マネタイズ = 無料出荷・サブスク先送り (SPEC §5 維持)、将来ゲートは「窓の拡張」で切り retention/コアは全期間無料・正準は全期間保存

## 文脈

リリース直前に「最初からサブスクを入れるか / 入れるならどの機能を制限するか」を検討した。競合 (Streaks / HabitKit / Habitica / Productive / Fabulous / Finch / Habitify / Way of Life 等) のマネタイズと、knockon の実装状態を突き合わせた ([ADR-0047](0047-settlement-lifecycle-and-log-portfolio.md) の起点となった検討)。

前提: prime objective は収益最大化ではなく「自分が毎日使う 1 本を最短で完成・出荷」。SPEC §5 / CLAUDE.md §5 は一貫して「サブスク有料機能は v1 非スコープ」と記録してきたが、専用の判断ログはなく設計の中身は白紙だった。今回それを検討し、方針を明文化する。

主要な調査知見 (事実):
- 「無料 3 習慣まで、あとは課金」は App Store レビュー最頻の不満。履歴・基本統計・リマインダー・同期を課金裏に隠すのは離反を招く (resent 側ゲート)。テーマ / 詳細分析 / 高度テンプレは相対的に許容される (tolerate 側)。
- サブスクは category (毎日開くが毎月の新機能を求めない) と個人開発事情 (churn 悪化・subscription fatigue・毎月の価値証明困難) の両方で逆風。ローカル / 同期なしの knockon は「継続提供価値」が薄くサブスク正当化が弱い。Streaks 買い切り支持・HabitKit のライフタイム併売 ($32-42) が近い先行事例。
- knockon はチェーン数に上限がなく、「習慣数制限」ゲートはむしろ人工的に作り込む必要がある = 無料側に有利。

## 検討した選択肢

- **案 A (採用): 無料出荷・課金先送り**。IAP なしで 100% 無料リリース。Phase 1 完成ゲート (毎日使えるか) と継続率データを先に取り、マネタイズは実利用後に判断。
- **案 B (却下): 買い切り Pro 型 (HabitKit 型)**。無料 generous コア + Pro 一括解禁 (分析 / メトリクス / Notion / 場所自動化 / プレミアムテンプレ)。将来の有力候補として構造は残すが、出荷時点では入れない。
- **案 C (却下): サブスク型**。ローカルのみで継続提供価値が薄く正当化が弱い。churn / 返金 / 「3 習慣問題」リスク大。ANT (マイナスを指差さない) とも衝突。
- **却下したゲート案: retention 短縮ゲート** (無料は直近 1 週間の履歴のみ)。(1) データを消すなら正準データ原則 (ADR-0001 / K-002) 違反、(2) 表示ゲートでも「積み上がり = プロダクトの主役」を自傷、(3) 市場的にも resent 側で Way of Life は履歴を無料化する方向。三重で却下。

## 決定

**案 A を採用。v1 は無料出荷、サブスクは先送り (SPEC §5 の非スコープ境界を維持)。**

将来もし課金するときの原則を先に固定する (今実装はしない):
1. **コアは全期間無料**: Today + active チェーン全表示 + ノードタップ + 通知 + スパイン + 定着ポートフォリオ + 累計 / 定着カウント。ここは絶対にゲートしない (Augmentation / ANT の核)。
2. **ゲートは「retention 短縮」でなく「派生ビューの窓を無料ベースラインの外側へ拡張」で切る**。無料 = 60D マトリクス / 定着ポートフォリオ (習慣形成 1 サイクル相当の俯瞰)、Pro = より長期の履歴 / 深掘り。無料窓を削るのではなく Pro で伸ばす。
3. **正準データは tier に関わらず常に全期間保存**。アップグレードは「失っていた履歴が戻る」ではなく「ずっと裏で記録され続けた全履歴が点灯する」体験 (マイナスを指差さない)。
4. tolerate 側 (分析深度 / メトリクス / Notion / 場所自動化 / プレミアムテンプレ) のみゲート候補。習慣数上限やコアループのゲートはしない。

## 理由

- **prime objective と早期検証ゲート ([ADR-0006](0006-phase1-completion-and-scope-narrowing.md)) に直結**: 検証前にマネタイズを作り込むのは [K-001](../../KNOWLEDGE.md)/[K-004](../../KNOWLEDGE.md) の罠。継続率という拘束条件に触れてから課金を判断する。
- **後付けの機会損失がほぼゼロ**: 正準データが固定・派生非保存のため、課金ゲートは無移行で後から足せる ([ADR-0047](0047-settlement-lifecycle-and-log-portfolio.md) の分析 IA も「任意 + 疎結合」構造のまま)。今作らない不利益が小さい。
- **サブスク正当化が弱い / retention ゲートは原則違反**: 上記文脈のとおり。knockon の思想 (Celebrate 主 / 積み上がりが主役 / ローカル) に最も近いのは Finch (コアをゲートせず装飾・加速のみ) と HabitKit (買い切り併売) で、いずれもサブスクでコアを人質に取らない。

## 想定される影響

- **SPEC §5 / CLAUDE.md §5**: 「サブスク v1 非スコープ」は維持 (覆さない)。本 ADR はその理由付けと将来ゲート原則を back-fill するもの。矛盾なし。
- 将来マネタイズを実装する時は本 ADR を参照し、「窓拡張ゲート・コア全期間無料・正準全保存」の原則に沿う。retention ゲート / コア課金 / サブスク型を再提案する場合は本 ADR を supersede する新 ADR が必要 ([K-005](../../KNOWLEDGE.md) 系譜維持)。
- 覆すコスト (低): 無料出荷なので課金導線の実装負債がない。方針転換は新 ADR + IAP 実装で対応。
