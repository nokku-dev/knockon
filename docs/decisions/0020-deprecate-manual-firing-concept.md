# 「手動発火」ワードを廃止し、 Today に並ぶ active チェーン全表示 + タップ達成を「日常フロー」と再定義する

## 文脈

[ADR-0003](0003-firing-logic.md) §決定 第 3 項で「**手動発火は v1 必須・行動アンカー成立の中核**」と書かれていた。 これは「自動発火 (時刻 / 場所) が機能しなくても、 ユーザーが手動でチェーンを開始できる」という設計意図。

しかし PR-1.5b-2 (通知実装) 時にユーザーが「**手動発火導線って今どうなってる?**」と確認したところ:

- 現状の Today は `useTodayData.ts:69` で `chains[0]` (先頭 1 active チェーンのみ)
- これは Phase 1.4 N=1 (シードチェーン 1 本前提) 時代のコード
- 「手動発火」を発動する別画面 / 別 UI は存在しない
- 「手動発火」 = 「ユーザーが Today を開いてノードをタップする」自然なフローのこと、 と判明

ユーザーの結論: 「**`手動発火` というワードは紛らわしいので廃止したい。 active / stocked の 2 状態と Today の全表示で要件は満たされる**」。

## 検討した選択肢

- **案 A**: ADR-0003 を superseded にして新たな発火モデルを定義 — 大規模変更、 場所/時刻発火の話まで巻き込む
- **案 B**: 「手動発火」ワードだけ廃止、 ADR-0003 §決定 第 3 項を再解釈 — ADR-0003 本体の発火ロジックは維持、 ワードの定義だけ変える
- **案 C**: そのまま放置 — 「手動発火」ワードが KNOWLEDGE / SPEC / CLAUDE.md に残り続け、 未来の自分や AI agent が誤読する

## 決定

**案 B** を採用。 「手動発火」ワードを廃止し、 以下に再定義:

- **Today に並ぶ active チェーン (全表示)** を「ユーザーが見て、 タップで達成記録する日常フロー」と呼ぶ
- 別画面 / 別ボタンの「発火 UI」は **作らない**
- ADR-0003 §決定 第 3 項の文言は意味的に保持されるが、 「手動発火」 = 「Today 表示 + タップ」と再解釈
- 同時に PR-X で `chains[0]` バグを修正、 全 active チェーンを Today に並べる (= 真の「全表示」が成立)

## 理由

- **「占拠防衛 = active / stocked」の要件で足りている**: 「使わなくなったチェーンを片付ける」は stocked で実現。 active なものは全部 Today に出す = 認知負荷ゼロ。
- **Augmentation 原則と整合**: 「手動発火」を専用 UI として作ると「ユーザーが追加の動作を覚える」必要が生じる。 Today に出ているものをタップ = 既存メンタルモデル踏襲。
- **ADR-0003 の意図と矛盾しない**: ADR-0003 が言うところの「手動発火」は「自動発火 (時刻/場所) なしでもチェーンが進む経路」を保証するもの。 Today に全 active が並んでタップで進む経路は、 ADR-0003 の意図を満たす。
- **ワードを廃止する判断のコスト**: SPEC / CLAUDE.md / KNOWLEDGE / コードコメントの「手動発火」を順次置換する作業が必要。 ただし軽微 (検索 + 置換)。

## 想定される影響

### 即時の影響

- `useTodayData.ts:69` の `chains[0]` を全 active 取得に変更 (PR-X で実装)
- `TodayScreen.tsx` を複数チェーン縦並びに改修 (PR-X、 [ADR-0021](0021-today-multichain-bottom-sheet.md) と並行)
- SPEC.md / CLAUDE.md / 既存 ADR-0003 を「Today 表示 + タップ」表記に置換

### 将来の覆すコスト

- **「手動発火」を復活させたい場合**: 別画面の発火 UI を新たに設計する別 ADR が必要。 ただし「Today 表示 + タップ」で機能している前提なので、 復活させたい強いユースケース (例: 通知を見て即発火したい、 ロック画面から直接) が出るまで保留。
- **ADR-0003 の文言整理**: 本 ADR でワード廃止を決めたが、 ADR-0003 の本文には「手動発火」が残る。 双方向リンク (K-005) で本 ADR を ADR-0003 から参照させ、 「§決定 第 3 項は ADR-0020 で再定義」と明示する。

### 注意点

- ADR-0003 を superseded にしない判断は意図的。 ADR-0003 §1〜2 (場所発火 / 時刻発火 / 有料 API 禁止 等) は今も load-bearing なため、 第 3 項だけを再解釈する形を取る ([K-015](../../KNOWLEDGE.md) 「全称禁則の軸別拡張」パターンの応用)。
- 「手動発火」ワードを完全に消すか、 「再定義したワードとして残す」かは判断点。 本 ADR は前者 (完全に消す) を採用 — 「Today に並ぶ active チェーン」と直接表現する方が読者の認知負荷が低い。
